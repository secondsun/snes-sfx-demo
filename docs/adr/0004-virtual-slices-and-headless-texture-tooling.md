# Virtual Slices, Descriptor Aliases, and Headless Agent Texture Tooling

To enable autonomous agents and automated build pipelines to author, pack, and update SuperFX texture atlases without launching desktop GUI environments or requiring manual assembly patching, `snes-sfx-demo` adopts the following architecture:

1. **Headless CLI & Subprocess MCP Tooling**: `texture-packer` provides a headless `CliMain` entrypoint with `pack` and `import` subcommands, packaged into an executable jar and exposed to agent workflows via the `sfx_pack_textures` tool in `retro-superfx_lsp`.
2. **First-Class Virtual Slices & Aliases in `.sfxproj`**: `ProjectDto` natively supports `slices` (sub-rectangles of existing Source Textures, such as $32 \times 16$ parapet panels and $16 \times 32$ foliage fins) and `aliases` (alternate symbolic identifiers mapping to existing descriptor indices, such as `water_deep`). Slices and aliases emit complete 8-byte `Texture Descriptors` and symbolic ca65 constants into `TEXTURE_TABLE` without allocating duplicate texels or violating power-of-two wrap constraints.
3. **Link-Time Bank 4 Address Relocation**: `AtlasIndexGenerator` targets the SuperFX linker contract by generating `.segment "GSUDATA"`, importing `textures_binary`, exporting `TEXTURE_TABLE`, and emitting `.word .loword(textures_binary + <offset>)` descriptor entries directly, matching the requirements of [ADR 0003](0003-non-square-textures-and-descriptors.md).
4. **Native ASCII Grid & Dual-Generation Pipeline**: `ProjectTextureDto` supports a 2D `pixelsAscii` format (where `.` represents transparent index 0, and `1..F` represent palette indices 1..15) alongside raw `pixelsHex`. Agents can draft crisp pixel art directly as human-readable ASCII grids or import external bitmaps through global 15-color Median-Cut quantization.
5. **Canonical Manifest Co-Location & Framebuffer Verification**: Each scene or engine maintains its authoritative `.sfxproj` manifest directly within its data directory (e.g. `snes-sfx-demo/X-GSU/IsoEngine/Data/TEXTURES.sfxproj`). Any modifications to active scene atlases are gated on headless Mesen framebuffer verification (`capture_sfx_render`) confirming `non_black_pixels > 0`.
