# Watertight Lattice Projection, Archetype Trapezoid Caching, and Pre-Shifted Atlas V Coordinates

To render Final Fantasy Tactics-style $N \times M$ tactical battlefields on the SuperFX (GSU / FX3) without blowing GSURAM or the 512-byte instruction cache, `IsoEngine` replaces scene-wide 3D mesh projection (`MODEL_V3` $\to$ `CACHED_TRIS`) with a four-part architecture:

1. **Watertight Integer Basis Lattice (`LATTICE_V2`)**: Because the 30-degree orbital-isometric camera is orthographic, all $32 \times 32$ Map Cells and canonical Shape Archetypes project identically up to a 2D screen translation. When camera `yaw` changes, the engine computes integer screen basis vectors $\vec{S}_x = (\text{round}(32\cos\theta), \text{round}(16\sin\theta))$, $\vec{S}_z = (\text{round}(-32\sin\theta), \text{round}(16\cos\theta))$, and Half-Block elevation step $\vec{S}_y = (0, -14)$ ($1\text{h} = 16$ world units). Both Map Cell screen anchors and the 28-point canonical tile lattice are constructed exclusively by integer additions and right-shifts of $(\vec{S}_x, \vec{S}_z, \vec{S}_y)$, guaranteeing zero 1-pixel rounding seams between adjacent cells, wedges, and skirts at all 120 yaw angles.
2. **Archetype-Level Pre-Solved Trapezoid Cache (`ARCH_TRAPS`)**: Rather than projecting and caching triangles for every cell on the map, Pass 0 projects only the canonical Shape Archetype pool (Flat, Straight/Outer/Inner Wedges, Stairs, Edge Panels, Liquid, Pillar, Foliage Cross, and Cell Skirts), backface-culls visible faces (`cross > 0`), solves per-face affine UV gradients `(du_dx, dv_dx)` and edge slopes `(dxL_dy, dxR_dy, du_dy, dv_dy)` once via `reciprocal_lookup_rom`, and splits faces into uniform horizontal scanline trapezoids (`cached_trap`). Both Pass 0 (left 128px Frame Half) and Pass 1 (right 128px Frame Half) then walk the $N \times M$ Map Grid in yaw-quadrant Painter's order (requiring zero runtime depth sorting), culling each Map Cell's bounding box against the active Frame Half and stamping its exposed Cell Skirts, Edge Panels, and Shape Archetype trapezoids.
3. **`ATLAS_STRIDE_SHIFT`-Parameterized Fixed-Point $V$**: Because the FX3 coprocessor lacks a hardware `MERGE` instruction and the 512-byte GSU instruction cache cannot afford variable multi-bit shift loops per pixel, vertical texture coordinates $V$ and gradients $dV$ are stored in `Q(16 - ATLAS_STRIDE_SHIFT).(ATLAS_STRIDE_SHIFT)` fixed-point (e.g., Q10.6 for a 64-wide atlas, Q8.8 for a 256-wide atlas). This places the integer texel bits of $V$ directly at bit position `ATLAS_STRIDE_SHIFT`, reducing per-pixel atlas row indexing `(tv & v_mask) << ATLAS_STRIDE_SHIFT` across any power-of-two Texture Atlas (`16` to `256`) and Source Texture size to a single `and v_mask_shifted` instruction.
4. **8-Byte `map_cell` &Lowest-Opaque-Floor Skirt Rule**: Each Map Cell is represented in 8 bytes (`base_height`, `archetype_id` + rotation, 1-byte `top_tex_id`, `skirt_tex_id`, and `panel_tex_id` indices into `TEXTURE_TABLE`, `panel_flags` with 4-bit N/E/S/W `panel_mask`, and baked N/S/E/W neighbor skirt drops). `base_height` is strictly the lowest opaque floor of the cell so that exposed Cell Skirts drop to $\max(0, h_{\text{cell}} - h_{\text{neighbor}})$ and closer neighbors naturally overdraw slopes, stairs, or translucent dithered water planes in Painter's order.
